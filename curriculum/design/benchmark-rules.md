# 已确认教材质量标杆规则

状态：`用户已确认`

确认日期：`2026-07-28`

标杆来源：`curriculum/units/M11/release-candidate.md`

本文件只抽取 M11 获得用户认可的叙事密度、代码解释颗粒度、图文关系、实践难度、迁移方式和面试表达。它不要求后续单元复制 M11 的标题、段落数或相同代码形状。

## 1. 叙事与深度

- 从一个真实运行问题进入，先让学习者知道正在解决什么，再引入源码符号。
- 沿一次真实运行连续讲清输入、状态、投影、组件交互、失败、恢复和输出，不按函数目录拼装。
- 每个决定性代码片段都要解释它改变了什么控制流、状态或语义，不只翻译函数名。
- 正文支持 4 至 7 小时主体学习；实验、故障注入和扩展挑战另计，不为压缩篇幅删掉机制深度。

## 2. 图文节奏

- 复杂单元可以先给一张全局图，建立运行地图和真实汇合点。
- 章首总图不能承担全章所有细节。当后续新增多层投影、状态所有权、重要分支、反馈循环、取消恢复或跨组件时序时，就地增加局部图。
- 依问题选择图类型：调用路径用流程图，跨组件时间顺序用时序图，轮转与恢复用状态图，可变容器与观察者关系用所有权图。
- 每张图只回答一个主问题，节点名与正文术语一致，箭头有明确动作或条件，正常与失败路径不混画。
- 图既要帮助初次理解，也要能在复习时独立唤起当前机制。图量由认知转折决定，不设配额，不用装饰性图示充数。
- 图中的运行边、状态归属和分支必须回到真实源码或实验核验，Graphify 不是图的最终证据。

## 3. 代码与语言前置

- 只展示改变语义的决定性源码，其余用路径、符号、分支和辅助行号定位。
- TypeScript/Node/React 难点在第一次改变当前机制时就地讲清：最小语义、当前作用、Java/Python 对照、常见误解和可运行验证。
- 对浅复制、深复制、流、生成器、取消和闭包等语言概念，必须说明它们改变了哪个状态或生命周期边界。

## 4. 实验与 Harness

- 先写要验证的结论，再给输入、观察点、预期现象和反证条件，不用“运行成功”代替机制验证。
- 至少保留一个能改变语义的破坏实验；高风险机制增加代表性取消、竞争、崩溃或恢复验证，不穷举每个 `catch`。
- TypeScript 和 Python 遵守同一行为契约而不逐行翻译。Harness 每次演进都说明新增契约、状态所有者、失败语义、兼容影响和回归结果。
- 明确区分 Claude Code 快照事实、clean-room 运行验证与作者设计迁移。

## 5. 企业迁移与面试表达

- Java/Spring、RAG、LangGraph 和企业治理由当前机制的所有权、协议、取消、恢复或观测边界自然推出，不在末尾突然堆一组通用架构术语。
- 以互联网大厂 Agent 开发岗的资深面试官视角，提出会直接涉及或可能延伸到当前内容的高价值问题。
- 核心问题提供口语化约两分钟回答：第一句先给结论，再展开运行机制，随问题自然落到 Claude Code 决定性设计、源码锚点、失败边界、权衡和企业方案。
- 回答要像面试现场可以即时组织的表达，不写成论文、口号或难以背诵的完美长句。
- 题量由本单元机制广度和面试价值决定，不设固定配额，不用题库堆积替代深度教学。

## 6. 后续教学闸门必查

- 是否保持真实问题驱动的连续叙事，而不是栏目拼装。
- 每个重要认知转折是否有足够近的图或代码解释，图文、方向、状态所有权和实验是否一致。
- 初学者是否能不依赖答案完成复述、画图、定位、运行、破坏、修复和迁移。
- 面试题是否具有真实资深岗位追问价值，约两分钟回答是否结论先行、机制准确、口语自然且能承接追问。
